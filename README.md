# Kim — الإصدار 1.0.0 (المرحلة الثانية عشرة: الجودة والإصدار)

تطبيق Flutter Web محلي لإدارة المساحة المالية الشخصية. يشمل المحافظ والعمليات والتحويلات والداشبورد والتصنيفات والميزانيات والادخار والديون والاشتراكات والإشعارات والتقارير والعملات والتصدير العربي، والإعدادات وقفل PIN والنسخ الاحتياطي المشفر والاستعادة الذرية. المرحلة الثانية عشرة والأخيرة تختبر الدورة المالية كاملة وتحسن الأداء والشاشات الصغيرة وتجهز بناء ويب إنتاجيًا مستقرًا.

## المرحلة الثانية عشرة — الجودة والإصدار

- اختبار تكاملي لدورة مالية كاملة على قاعدة ملفات حقيقية تُعاد فتحها بين
  المراحل: محافظ ودخل ومصاريف وتعديل وحذف وتحويلات بعملتين ورسوم وإلغاء
  وميزانية وهدف ادخار محمي وديون وسداد معدّل وملغى واشتراك تلقائي وتقرير
  ولوحة تحكم ونسخة مشفرة واستعادة ونسخة رجوع. كل رصيد يُعاد حسابه مستقلًا
  من السجلات الفعالة ويطابق السجل المحاسبي.
- مصفوفة واجهات لكل الصفحات بعرض 320 و360 و768 و1024 و1440 بكسل، بالعربية
  والإنجليزية والثيمين، ولجميع نوافذ التحرير بعرض 320 بكسل.
- إصلاحات: تجاوز الشريط العلوي على الهواتف الضيقة مع PIN، وعنوان الصفحات
  الطويل على سطح المكتب الضيق، وانهيار شريط تقدم ميزانية متجاوزة 100%.
- أداء: التحقق من التواريخ دون بحث المنطقة الزمنية وتعابير منتظمة مُجمّعة
  مسبقًا؛ تحميل 2000 عملية أسرع بنحو 4.5 مرات وإنشاء العملية أسرع بنحو مرتين.
- كاش العمل دون إنترنت يضم الملفات التي يطلبها المحمّل فعلًا: 21.7 MiB بدل
  45.5 MiB. شاشة التحميل تتبع الوضع الداكن وتعرض رسالة عند تعطيل JavaScript.

راجع [تقرير المرحلة الثانية عشرة](docs/phase-12-report.md) و[دليل النشر](docs/release.md).
فحص الإصدار: `npm run test:release --prefix tool`.

## المرحلة الحادية عشرة

تتحكم الإعدادات باللغة والثيم وعملة العرض والخصوصية. قفل PIN يحمي واجهة
الجلسة ولا يشفّر قاعدة المتصفح ولا يمنع أدوات المطور. الملف الاحتياطي
يمكن تشفيره بكلمة مرور مستقلة باستخدام AES-256-GCM وPBKDF2-SHA256.
لا خدمة لاستعادة كلمات مرور الملفات المنسية.

الاستعادة تفحص الملف والعلاقات في قاعدة مؤقتة قبل عرض تأكيد صريح، ثم
تستبدل البيانات كلها داخل معاملة واحدة مع حفظ نسخة رجوع محلية. النسخ
تحتفظ بمعرفات العمليات والبيانات الأصلية ولا تدمج الأرصدة أو تسجلها مرتين.
راجع [تقرير المرحلة الحادية عشرة](docs/phase-11-report.md) للحدود والتحقق
والتوافق. فحص المتصفح: `npm run test:security --prefix tool`.

## المرحلة العاشرة

التقارير تستند إلى العمليات الحقيقية وتفصل أصل الدين والتحويلات الداخلية
عن الدخل والمصاريف، مع فلاتر ورسوم تفاعلية ومقارنة الفترة السابقة.
عملة العرض وأسعار التقييم اليدوية مشتركة مع الداشبورد ولا تغيّر أي مبلغ
أصلي. التحويل المفقود يظهر كإجمالي غير مكتمل.

التصدير يعمل دون إنترنت بخطوط عربية مضمّنة. Excel ملف XLSX حقيقي،
وتحفظ مبالغه كنص دقيق لحماية الأرقام الكبيرة. الويب ينزّل الملفات؛
المنصات الأصلية تحفظها داخل مستندات التطبيق وتعرض المسار.
راجع [تقرير المرحلة العاشرة](docs/phase-10-report.md) لقواعد الحساب وحدود
التقييم والتفاصيل الفنية. فحص المتصفح: `npm run test:reports --prefix tool`.

## التشغيل

يتطلب Flutter 3.47.2 أو أحدث متوافقًا مع Dart 3.13، وChrome.

```powershell
flutter pub get
flutter run -d chrome --web-port=8080
```

استخدم المنفذ نفسه دائمًا؛ IndexedDB مرتبط بعنوان الموقع والمتصفح والمنفذ.

## بناء نسخة تعمل دون إنترنت

```powershell
.\tool\build_web.ps1
```

أو عبر أي نظام:

```sh
flutter build web --release --no-web-resources-cdn --pwa-strategy=none
dart run tool/generate_offline.dart
```

اخدم مجلد `build/web` عبر localhost أو HTTPS؛ لا تفتح `index.html` عبر `file://`.
مثال إذا كان Python متاحًا:

```sh
python -m http.server 8080 --directory build/web
```

يُثبت عامل الخدمة الكاش بعد تنزيل كل ملفات البناء. بعد اكتمال التثبيت يمكنك
إعادة تحميل التطبيق دون شبكة. النسخة التطويرية `flutter run` ليست نسخة العمل
دون إنترنت. يجب إعادة توليد الكاش بعد كل بناء. عند تحديث الإصدار يُفعّل الكاش
الجديد بعد إغلاق تبويبات الإصدار القديم وإعادة فتح التطبيق، لتجنب خلط ملفات
الإصدارين. عند النشر داخل مجلد فرعي، مرر `-BaseHref /kim/` إلى سكربت البناء.

## ما يعمل الآن

- Riverpod لإدارة الحالة وحقن الاعتماديات، GoRouter لمسارات الصفحات الست والصفحات الفرعية للتحويلات والتصنيفات والأهداف والديون والاشتراكات والإشعارات والعملات.
- إعدادات فعلية: العربية/الإنجليزية وRTL/LTR، وثيم الجهاز/الفاتح/الداكن.
- حفظ إعدادات المتصفح في IndexedDB عبر Sembast Web، مع رسالة خطأ واضحة عند
  تعذر الحفظ أو فتح القاعدة. لا يوجد تراجع صامت إلى تخزين في الذاكرة.
- Design System موحد: ألوان، خطوط Noto محلية مرخصة OFL، أزرار، بطاقات، حقول
  نماذج، نوافذ حوار وتنقل متجاوب. لا توجد خطوط أو موارد renderer من CDN.
- محافظ فعلية ببطاقات وتفاصيل وتخصيص الاسم واللون والأيقونة والنوع والعملة والرصيد الافتتاحي، وتعديل وأرشفة واستعادة وترتيب وإخفاء رصيد.
- حالات فارغة صادقة لكل صفحة؛ لا توجد بيانات مالية وهمية.
- `Money`: وحدات صغرى `BigInt` مع عملة ودقة صريحة، تحليل عشري صارم دون تقريب،
  تخزين نصي آمن لقيم أكبر من حد JavaScript، ورفض جمع العملات أو الدقات المختلفة.
- `OperationId`: UUID v4، و`AppDatabase.applyOnce` ينفذ الكتابة ووصل منع التكرار
  في معاملة ذرية. إعادة نفس الطلب بنفس المعرّف لا تكرر الكتابة؛ تغييره يرفض الطلب.
- تحويلات ذرية بين المحافظ، بسعر صرف يدوي دقيق ورسوم كمصروف مرتبط، وتعديل وإلغاء وسجل دائم.
- قاعدة إصدارها 11، وترحيلات محفوظة من الإصدارات 1–10، ورفض قواعد الإصدارات الأحدث.

## البنية

```text
lib/
  app/                     # bootstrap, app, routing, responsive shell
  core/
    domain/                # exact money and operation IDs
    data/                  # database, migrations, atomic receipts
    l10n/                  # all Arabic/English product copy
    platform/              # browser language metadata adapter
  shared/
    design_system/         # tokens, typography, theme, UI components
    widgets/               # page viewport and honest empty states
  features/
    settings/
      domain/              # settings entity and repository contract
      data/                # durable local repository
      presentation/        # controller and settings page
    dashboard/presentation/
    wallets/{domain,data,presentation}/
    transactions/{domain,data,presentation}/
    transfers/{domain,data,presentation}/
    budgets/{domain,data,presentation}/
    reports/presentation/
```

أضف Domain وData لكل ميزة عندما تُنفذ فعليًا؛ لا تُنشئ منطقًا أو مستودعات وهمية
للمراحل التالية. Presentation لا يصل إلى IndexedDB مباشرة. Domain لا يستورد
Flutter أو مكتبات التخزين. اعتماديات البناء مثبتة في `pubspec.lock`.

## ترحيل البيانات وسلامة العمليات

زِد `schemaVersion` عند تغير شكل البيانات وأضف خطوة ترحيل واختبارًا من الإصدار
السابق. Sembast ينفذ callback الترحيل في معاملة الافتتاح. لا تستبدل القاعدة أو
تمسحها عند خطأ الترحيل. دالة `applyOnce` تتطلب معرفًا ثابتًا وطلبًا canonical
ثابتًا عبر المحاولات. أنشئ المعرف والوقت خارج callback، واجعل كل تأثير فيه
كتابة باستخدام `Transaction` نفسه؛ قد يعيد Sembast Web تشغيل callback عند
تعارض التبويبات. لا تضع إشعارات أو اتصال شبكة داخل المعاملة.

## حدود الإصدار

الويب هو المنصة المدعومة والمختبرة حاليًا. لا يوجد Backend أو حساب مستخدم أو
مزامنة خارجية. بيانات المتصفح ليست نسخة احتياطية؛ مسح بيانات الموقع يحذفها،
والتصفح الخاص أو قيود المساحة قد تمنع الاحتفاظ بها. أول تحميل يحتاج اتصالًا
أو خادمًا محليًا؛ العمل دون شبكة يحتاج اكتمال الكاش على localhost أو HTTPS.
اختبار المتصفح الآلي على Chrome؛ لم تُختبر Safari أو Firefox آليًا بعد.

## المحافظ والسجل المالي

كل محفظة تنشأ بقيد افتتاحي دائم، حتى لو كان الرصيد صفرًا أو سالبًا. الرصيد
مجموع القيد الافتتاحي والتسويات والدخل والمصاريف وطرف التحويل والرسوم والقيود العكسية؛ لا يوجد حقل رصيد يمكن تعديله عشوائيًا. تصحيح
الرصيد يطلب القيمة الصحيحة والسبب، ويسجل الفرق والرصيد السابق واللاحق والتاريخ
ومعرّف العملية. العملة والقيد الافتتاحي لا يُعاد كتابتهما عند تعديل المحفظة.

تُعرض الأرصدة حسب العملة ودقتها دون جمع عملات مختلفة. يدعم الاختيار العملات
الشائعة ورمزًا مخصصًا من ثلاثة أحرف بدقة 0–6. الأرشفة تحتفظ بالسجل وتوقف التعديل
المالي حتى الاستعادة. الإخفاء يحجب المبالغ في البطاقة والتفاصيل والسجل والمجاميع
والنموذج المفتوح؛ وهو خصوصية عرض، وليس تشفيرًا لقاعدة البيانات.

اختبار Chrome للمرحلة الثانية، بعد بناء النسخة وتوليد الكاش وتشغيل الخادم:

```powershell
npm install --prefix tool
$env:KIM_URL='http://127.0.0.1:8765'
npm run test:wallets --prefix tool
```

[تقرير المرحلة الثانية](docs/phase-2-report.md) يتضمن الملفات والميزات والاختبارات
والقيود. المرحلة الثالثة موثقة أدناه.

## الدخل والمصاريف

أضف عملية من صفحة العمليات أو الرئيسية: اختر دخلًا أو مصروفًا والمحفظة
والتصنيف والمبلغ والتاريخ والملاحظات. المبلغ موجب وبعملة المحفظة ودقتها،
والرصيد يتغير فور الحفظ. سجل العمليات يدعم البحث والتصفية حسب النوع والمحفظة
والتصنيف والتاريخ والحالة، والتعديل والحذف المؤكد.

التعديل يعكس الأثر السابق ثم يسجل البديل، والحذف يلغي الأثر بقيد عكسي ويحفظ
العملية بحالة ملغاة. جميع الكتابات ذرية ومحميّة من التكرار والتعديل القديم
في تبويب آخر. العمليات القديمة تُرتب حسب تاريخها، لكن القيود تسجل بترتيب
الحفظ فلا تعيد كتابة تسوية سابقة. التاريخ المستقبلي يؤثر في الرصيد فورًا؛
لا يوجد نظام جدولة. المحافظ المؤرشفة تتطلب الاستعادة قبل تعديل عملياتها.

التصنيفات الجاهزة مترجمة؛ إدارة تصنيفات مخصصة ليست ضمن المرحلة الثالثة.
تغيير محفظة عملية أثناء تعديلها يصحح تخصيصها، وعند اختلاف العملة يطلب مبلغًا
جديدًا صريحًا؛ لا ينفذ تحويلًا أو سعر صرف. الإخفاء يحجب المبالغ في سجل العمليات
والرئيسية والنماذج المفتوحة، بما في ذلك أثناء إعادة تحميل بيانات المحافظ.

```powershell
npm run test:transactions --prefix tool
```

## التحويلات بين المحافظ

افتح «التحويلات» من صفحة المحافظ. اختر محفظتين نشطتين والمبلغ والرسوم
والملاحظات، أو بدّل المحفظتين لتحويل بالاتجاه الآخر. الرسوم بعملة المصدر.
عند اختلاف العملات أدخل سعرًا يدويًا: وحدة من عملة المصدر تساوي السعر بعملة
الاستلام. يدعم السعر حتى 12 منزلة عشرية وأرقامًا عربية؛ يحفظ مع العملية.
المبلغ المستلم يُحسب باستخدام BigInt ويُقرب لدقة عملته، والنصف إلى الأعلى.
العملة نفسها تستخدم السعر 1 حتى لو اختلفت الدقة. تُعرض المعاينة قبل الحفظ.

الخصم والإضافة والرسوم وسجل التحويل ووصل منع التكرار تُحفظ في معاملة واحدة.
أصل التحويل ليس دخلًا أو مصروفًا؛ الرسوم فقط مصروف مرتبط، ولا تُعدل أو تُحذف
من سجل العمليات مباشرة. التعديل والإلغاء يعكسان الآثار السابقة مع إبقاء
السجل ومعرّف التحويل على الطرفين. يُرفض أي خصم صافٍ لا يغطيه الرصيد الحالي،
بما فيه إلغاء تحويل صُرف مبلغ الاستلام منه. لا يعيد التعديل كتابة السجل.
التعديل الذري يفحص الأرصدة النهائية، لذا قد يوجد رصيد مؤقت سالب داخل قيود
عكس واستبدال عملية واحدة دون أن يُنشر للمستخدم كرصيد مستقل.

إخفاء إحدى المحفظتين يحجب مبالغ طرفي التحويل، لأنها قد تكشف بعضها بسعر الصرف.
الخصوصية تشمل النموذج المفتوح وتحديث البيانات بين التبويبات. الأرشفة تمنع
تغيير التحويل قبل استعادة المحفظة المعنية. إدارة العملات المتقدمة وأسعار
الصرف التلقائية ليست ضمن هذه المرحلة.

```powershell
npm run test:transfers --prefix tool
```

ولا دمج في main دون طلب صريح.


## لوحة التحكم — المرحلة الخامسة

- بطاقات الرصيد الحالي والدخل والمصاريف وصافي التدفق النقدي محسوبة من السجل المحلي الحقيقي، مع بطاقات المحافظ النشطة وآخر خمس عمليات دخل/مصروف/تحويل.
- الفترة: هذا الشهر، الشهر الماضي، آخر سبعة أيام، هذه السنة أو نطاق مخصص شامل لليومين. تتبع العمليات تاريخها المالي؛ يتبع التحويل تاريخ إنشائه المحلي، لأن التحويلات الحالية لا تحتوي تاريخًا ماليًا منفصلًا.
- الرصيد هو الرصيد الحالي للمحافظ النشطة؛ تغيير الفترة يغير التدفقات والرسوم والسجل فقط. تدفقات المحافظ المؤرشفة محفوظة ضمن الفترات التاريخية.
- اختيار عملة العرض يتضمن دقتها. لا تُجمع العملات أو الدقات المختلفة. يظهر تنبيه «الإجمالي غير مكتمل» عند استبعاد عملات أخرى؛ أسعار التحويل التاريخية ليست أسعار تقييم عامة، ولا يجري تخمين سعر صرف.
- أعمدة تفاعلية للدخل والمصاريف (حتى 12 مجموعة تاريخية متجاورة)، ودائرة لتوزيع الإنفاق مع اختيار التصنيفات. الأرقام المالية `BigInt`؛ الكسور التقريبية المحدودة تُستخدم لرسم الأشكال فقط.
- الاختصارات تفتح نماذج الدخل والمصاريف والتحويل الموجودة، مع اختيار نوع العملية مسبقًا. الإخفاء يحجب الأرقام والرسوم التي قد تكشف مبالغ المحافظ المخفية، ولا يُعرض محتوى قديم أثناء إعادة تحميل الخصوصية.
- لم تُضف حزم أو موارد خارجية أو مخازن مكررة. التحويلات الداخلية لا تدخل التدفق النقدي، ورسومها تدخل المصاريف مرة واحدة.

```powershell
npm run test:dashboard --prefix tool
```

راجع [تقرير المرحلة الخامسة](docs/phase-5-report.md) ونتائج المتصفح في `docs/phase-5-browser-validation.json`.
أُضيفت التقارير وأسعار الصرف العامة في المرحلة العاشرة الموثقة أعلى الصفحة.
التخصيص الدائم لترتيب البطاقات يبقى لمرحلة لاحقة. التصنيفات والميزانيات موثقة أدناه.


## التصنيفات والميزانيات — المرحلة السادسة

افتح **إدارة التصنيفات** من صفحة العمليات أو الميزانيات. أضف تصنيف دخل أو
مصروف باسم ولون وأيقونة، وعدله أو أرشفه أو استعده. التصنيفات الافتراضية
مترجمة ويمكن تخصيص اسمها ولونها وأيقونتها. لا يتغير نوع التصنيف بعد إنشائه.
حذف تصنيف مخصص غير مستخدم متاح بعد تأكيد؛ التصنيف المرتبط بعملية، حتى لو
كانت ملغاة، أو بميزانية يُحتفظ به ويمكن أرشفته. تصنيف رسوم التحويل محفوظ
للنظام ولا يُحذف أو يؤرشف.

أنشئ ميزانية **شهرية أو أسبوعية**، عامة أو لتصنيف مصاريف، بمبلغ موجب وعملة
ودقة محددتين. تاريخ أول فترة يقبل أي يوم داخلها ويُحفظ بدء تلك الفترة.
الأسبوع من الإثنين إلى الأحد، والشهر تقويمي. يتجدد الحد لكل فترة دون ترحيل.
اعرض الفترات السابقة واللاحقة بالأسهم أو اختر تاريخًا محددًا من التقويم.

- المخطط والمصروف والمتبقي ونسبة الاستخدام وشريط التقدم تأتي من السجلات
  الفعلية. المصروفات الملغاة والدخل وأصل التحويل مستبعدة؛ الرسوم تدخل مرة واحدة.
- كل ميزانية بعملتها ودقتها، دون تحويل تخميني. العامة وتصنيفاتها تتداخل، لذلك
  لا تُجمع أرقامها في «إجمالي إنفاق» مكرر.
- تنبيهات داخل التطبيق عند حدود تختارها من 50% و80% و100%، بحد أعلى واحد
  لكل ميزانية وفترة. تظهر في بطاقة الميزانية وعلى الرئيسية للفترة الحالية.
  تُعاد الحسابات عند تعديل مبلغ أو تاريخ أو تصنيف عملية قديمة أو حذفها.
- إخفاء محفظة ذات صلة يحجب المبالغ والنسبة وشريط التقدم والتنبيه. تدفقات
  المحافظ المؤرشفة تبقى محسوبة في تاريخها، كما في لوحة التحكم.
- تعديل تعريف الميزانية يطبق على كل فتراتها؛ لا توجد نسخ تاريخية مستقلة
  للمبلغ المخطط. الميزانيات المؤرشفة قابلة للاستعادة؛ حذفها لا يحذف العمليات.
- قاعدة البيانات بالإصدار 6؛ الترقية تحفظ بيانات المراحل السابقة وتضيف
  التصنيفات الافتراضية مرة واحدة، دون إنشاء معاملات أو أرصدة وهمية.

```powershell
npm run test:planning --prefix tool
```

الفحص يستخدم Chrome وIndexedDB الفعليين. لاختبار الترقية من الخامسة، شغّل
`node tool/seed_phase5_browser.cjs` ضد بناء الخامسة أولًا، ثم ابن السادسة
على العنوان والمنفذ نفسيهما، ومرر مسار ملف الاختبار المطبوع عبر
`KIM_LEGACY_PROFILE` قبل `test:planning`. هذا ملف متصفح اختبار معزول داخل
`.dart_tool`؛ لا تستخدم ملف متصفح شخصي. عند تحديث الإصدار، يجب إغلاق صفحات
الإصدار القديم حتى يكتمل تفعيل كاش الإصدار الجديد.

راجع [تقرير المرحلة السادسة](docs/phase-6-report.md) ونتائج
`docs/phase-6-browser-validation.json`. الإشعارات المحلية المجدولة والترحيل
التلقائي للفائض ونسخ التعريفات التاريخية تبقى لمراحل لاحقة.

## أهداف الادخار — المرحلة السابعة

افتح **أهداف الادخار** من الرئيسية أو الميزانيات. أنشئ هدفًا باسم ومبلغ
موجب وعملة ودقة وتاريخ ولون وأيقونة. تعرض بطاقته التقدم والمبلغ المخصص
والمتبقي والوقت حتى الموعد، أو التأخر عنه. الإحصائيات تميز الأهداف النشطة
والمكتملة التمويل والمغلقة، مع حالات فارغة بالعربية والإنجليزية.

**التخصيص حجز لأموال موجودة:** لا يغير الرصيد ولا ينشئ دخلًا أو مصروفًا.
تُعرض أرصدة المحافظ الفعلية والمحجوز لكل الأهداف والمتاح للصرف والتخصيص.
أدخل **إجمالي** تخصيص الهدف من المحفظة، وليس زيادة؛ تخفيضه يحرر الفرق
والصفر يحرره كله، مع الاحتفاظ بسجل مساهمات موقع ومؤرخ وملاحظة اختيارية.

- لا يُسمح بحجز نفس الأموال لهدفين أو تجاوز الهدف أو رصيد المحفظة المتاح.
  يجب تطابق العملة والدقة؛ العملات المختلفة لا تُجمع.
- للتحويل الفعلي، حرر الحجز، ثم استخدم **نقل أموال فعليًا** إلى محفظة
  الادخار، ثم خصص من المستلمة. التحويل والتخصيص خطوتان صريحتان؛ لا يوجد
  نقل تلقائي خفي أو محفظة وهمية إضافية.
- المصروفات وتعديلها أو نقلها، وحذف أو تعديل دخل قديم، والتحويلات ورسومها
  وتعديلها وإلغاؤها، والتسويات: كلها تحمي الحجوزات داخل نفس معاملة التخزين.
  تفحص التعديلات الأثر النهائي الكامل، دون رفض بسبب قيد عكسي وسيط.
- يمكن تعديل معلومات الهدف وزيادة مستهدفه. لتخفيض المستهدف تحت المخصص،
  حرر الفرق أولًا. عملة الهدف ثابتة. لا تؤرشف محفظة فيها حجز قبل تحريره.
- إغلاق الهدف نهائي ويحرر كل الحجوزات ذريًا، ويحفظ المبلغ عند الإغلاق
  والتقدم والسجل. التمويل الكامل يُحتسب من هذه اللقطة التاريخية؛ المبالغ
  المحررة لا تُحتسب كحجز حالي. يمكنك إنشاء هدف جديد لاحقًا.
- إخفاء رصيد محفظة مرتبطة يحجب مبالغ الهدف وتقدمه وإحصاء الإنجاز وسجل
  مبالغها، ويوقف النوافذ القديمة المفتوحة عند تغير البيانات في تبويب آخر.
- التخزين المحلي بالإصدار **7** يحفظ جميع بيانات المراحل السابقة دون
  إنشاء أهداف أو مساهمات افتراضية. الحسابات المالية بـ `BigInt`؛ الكسور
  العائمة تستخدم لرسم شريط التقدم فقط بعد حصر نسبته.

```powershell
flutter analyze --no-pub
flutter test --no-pub --concurrency=1
flutter build web --release --no-pub --no-web-resources-cdn --pwa-strategy=none
dart run tool/generate_offline.dart
npm run test:savings --prefix tool
```

راجع [تقرير المرحلة السابعة](docs/phase-7-report.md). لا توجد مساهمات دورية
تلقائية أو تذكيرات مجدولة؛ الموعد للعرض والمتابعة. السادسة والسابعة محفوظتان
على فروع محلية مستقلة إلى أن يُطلب رفعهما.

## الديون والقروض — المرحلة الثامنة

افتح **الديون والقروض** من الرئيسية أو المحافظ. أضف سجلًا لما أقرضته
أو اقترضته، باسم الشخص والمبلغ الأصلي وعملته واستحقاقه وملاحظاته.
إنشاء السجل لا يغير النقد. استخدم **تسجيل أصل الدين نقديًا** فقط عند
الحاجة لإثبات صرف أو استلام الأصل في المحفظة، ثم سجل الدفعات الجزئية
أو الكاملة بشكل مستقل. لا تعِد تسجيل أموال ضمن الرصيد الافتتاحي.

دفعات المال الذي أقرضته تضيف لمحفظتك؛ دفعات المال الذي اقترضته تخصم
منها. تعديل الدفعة أو محفظتها وإلغاؤها يحتفظ بقيود عكسية ويصحح الرصيد
والمتبقي والحالة ذرّيًا. السداد الزائد ونقص المتاح وحجوزات الادخار
محميّة. العملات والدقة يجب أن تتطابق، ولا تُصنف هذه الحركات كدخل أو
مصروف ولا تدخل الميزانيات.

الحالات النشطة والمتأخرة والمسـددة مشتقة من الرصيد المتبقي والاستحقاق،
مع فلاتر وسجل حركات دائم. تفاصيل الحسابات والحدود والتحقق في
[تقرير المرحلة الثامنة](docs/phase-8-report.md). قاعدة البيانات بالإصدار 8.

```powershell
npm run test:debts --prefix tool
```

## الاشتراكات والإشعارات — المرحلة التاسعة

افتح **الاشتراكات والمدفوعات** من الرئيسية، أو **مركز الإشعارات** من
الرئيسية وزر الجرس العام. أضف الاسم والمبلغ والمحفظة وتصنيف المصروف
والدورة والموعد القادم، وتابع التوقعات من التقويم. يمكن الإيقاف المؤقت
والتعديل والاستئناف والإلغاء مع حفظ المصروفات السابقة.

التسجيل التلقائي خيار صريح غير مفعّل افتراضيًا. في وضع التذكير، تسجل
الاستحقاق يدويًا بتأكيد. عند التفعيل، يعالج الفتح والعودة والمقدمة
المواعيد المتأخرة، بحد 100 دفعة في الجولة. كل خصم ومصروف وإيصال
وتقدم موعد معاملة واحدة تمنع التكرار بعد الانقطاع أو تعدد المعالجات.
نقص المتاح والحجوزات يوقفان الاستحقاق دون تجاوزه. تعديل أو حذف مصروف
مسجل لا يعيد تسجيل نفس الاستحقاق.

المركز الداخلي يعرض الاشتراكات والميزانيات والديون من بياناتها الفعلية
مع قراءة وإخفاء واستعادة محفوظة محليًا. الإشعارات المحلية بإذن صريح:
Android يجدول تذكيرات تقريبية؛ الويب يعرضها أثناء فتحه عند الدعم فقط.
**لا ضمان لعمل خلفي عند إغلاق المتصفح، ولا خصم مالي من إشعار النظام.**
إشعارات الجهاز عامة دون مبالغ أو أسماء؛ التنبيهات الخاصة تتبع إخفاء
المحافظ.

```powershell
npm run test:recurring --prefix tool
```

راجع [تقرير المرحلة التاسعة](docs/phase-9-report.md) للسياسات وحدود
المنصات ونتائج الاختبارات. التخزين بالإصدار 9، مع بقاء الويب وأندرويد
محليين دون تسجيل دخول أو خدمة خلفية خارجية.
