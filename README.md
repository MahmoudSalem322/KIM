# Kim — المحافظ والعمليات والتحويلات (المرحلة الرابعة)

تطبيق Flutter Web محلي لإدارة المساحة المالية الشخصية. هذه النسخة تشمل التأسيس والمحافظ والدخل والمصاريف والتحويلات الفعلية. الميزانيات والتقارير لم تُنفذ بعد.

## التشغيل

يتطلب Flutter 3.47.2 أو أحدث متوافقًا مع Dart 3.13، وChrome.

```powershell
flutter pub get
flutter run -d chrome --web-port=8080
```

استخدم المنفذ نفسه دائمًا؛ IndexedDB مرتبط بعنوان الموقع والمتصفح والمنفذ.

## بناء نسخة تعمل دون إنترنت

```powershell
.\tool\build_web.ps1
```

أو عبر أي نظام:

```sh
flutter build web --release --no-web-resources-cdn --pwa-strategy=none
dart run tool/generate_offline.dart
```

اخدم مجلد `build/web` عبر localhost أو HTTPS؛ لا تفتح `index.html` عبر `file://`.
مثال إذا كان Python متاحًا:

```sh
python -m http.server 8080 --directory build/web
```

يُثبت عامل الخدمة الكاش بعد تنزيل كل ملفات البناء. بعد اكتمال التثبيت يمكنك
إعادة تحميل التطبيق دون شبكة. النسخة التطويرية `flutter run` ليست نسخة العمل
دون إنترنت. يجب إعادة توليد الكاش بعد كل بناء. عند تحديث الإصدار يُفعّل الكاش
الجديد بعد إغلاق تبويبات الإصدار القديم وإعادة فتح التطبيق، لتجنب خلط ملفات
الإصدارين. عند النشر داخل مجلد فرعي، مرر `-BaseHref /kim/` إلى سكربت البناء.

## ما يعمل الآن

- Riverpod لإدارة الحالة وحقن الاعتماديات، GoRouter لمسارات الصفحات الست وصفحة التحويلات التابعة للمحافظ.
- إعدادات فعلية: العربية/الإنجليزية وRTL/LTR، وثيم الجهاز/الفاتح/الداكن.
- حفظ إعدادات المتصفح في IndexedDB عبر Sembast Web، مع رسالة خطأ واضحة عند
  تعذر الحفظ أو فتح القاعدة. لا يوجد تراجع صامت إلى تخزين في الذاكرة.
- Design System موحد: ألوان، خطوط Noto محلية مرخصة OFL، أزرار، بطاقات، حقول
  نماذج، نوافذ حوار وتنقل متجاوب. لا توجد خطوط أو موارد renderer من CDN.
- محافظ فعلية ببطاقات وتفاصيل وتخصيص الاسم واللون والأيقونة والنوع والعملة والرصيد الافتتاحي، وتعديل وأرشفة واستعادة وترتيب وإخفاء رصيد.
- حالات فارغة للميزانيات والتقارير؛ لا توجد بيانات مالية وهمية.
- `Money`: وحدات صغرى `BigInt` مع عملة ودقة صريحة، تحليل عشري صارم دون تقريب،
  تخزين نصي آمن لقيم أكبر من حد JavaScript، ورفض جمع العملات أو الدقات المختلفة.
- `OperationId`: UUID v4، و`AppDatabase.applyOnce` ينفذ الكتابة ووصل منع التكرار
  في معاملة ذرية. إعادة نفس الطلب بنفس المعرّف لا تكرر الكتابة؛ تغييره يرفض الطلب.
- تحويلات ذرية بين المحافظ، بسعر صرف يدوي دقيق ورسوم كمصروف مرتبط، وتعديل وإلغاء وسجل دائم.
- قاعدة إصدارها 5، وترحيلات محفوظة من الإصدارات 1–4، ورفض قواعد الإصدارات الأحدث.

## البنية

```text
lib/
  app/                     # bootstrap, app, routing, responsive shell
  core/
    domain/                # exact money and operation IDs
    data/                  # database, migrations, atomic receipts
    l10n/                  # all Arabic/English product copy
    platform/              # browser language metadata adapter
  shared/
    design_system/         # tokens, typography, theme, UI components
    widgets/               # page viewport and honest empty states
  features/
    settings/
      domain/              # settings entity and repository contract
      data/                # durable local repository
      presentation/        # controller and settings page
    dashboard/presentation/
    wallets/{domain,data,presentation}/
    transactions/{domain,data,presentation}/
    transfers/{domain,data,presentation}/
    budgets/presentation/
    reports/presentation/
```

أضف Domain وData لكل ميزة عندما تُنفذ فعليًا؛ لا تُنشئ منطقًا أو مستودعات وهمية
للمراحل التالية. Presentation لا يصل إلى IndexedDB مباشرة. Domain لا يستورد
Flutter أو مكتبات التخزين. اعتماديات البناء مثبتة في `pubspec.lock`.

## الاختبارات

```powershell
flutter analyze
flutter test
```

اختبارات المال تغطي الكسور والأرقام العربية والقيم الضخمة ورفض المدخلات غير
الصحيحة. اختبارات القاعدة تستخدم قاعدة ملفات حقيقية وتغطي إعادة الفتح والترحيل
والتكرار المتزامن والتراجع الذري. اختبارات الواجهة تغطي التنقل وحفظ الإعدادات
والثيم واللغة وRTL والأبعاد الصغيرة والوصول. اختبارات الإعدادات تغطي فشل الحفظ
والتغييرات السريعة المتتالية.

اختبار متصفح اختياري بعد بناء الويب وتشغيل خادم محلي على المنفذ 8765:

```powershell
npm install --prefix tool
$env:KIM_URL='http://127.0.0.1:8765'
$env:CHROME_EXECUTABLE='C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:browser --prefix tool
```

يشغّل اختبار المتصفح نسخة حقيقية، ويغير اللغة والثيم ويعيد تحميلها ثم يقطع
الشبكة ويعيد فتحها، ويفحص عدم وجود طلبات خارجية. يكتب التقرير والصور في `docs`.

لاختبار الحسابات على هدف JavaScript مستقلاً عن مشغّل اختبار Chrome في SDK:

```powershell
dart compile js tool/money_web_check.dart -o tool/money_web_check.js
$env:KIM_MONEY_JS=(Resolve-Path tool/money_web_check.js).Path
npm run test:browser --prefix tool
```

## ترحيل البيانات وسلامة العمليات

زِد `schemaVersion` عند تغير شكل البيانات وأضف خطوة ترحيل واختبارًا من الإصدار
السابق. Sembast ينفذ callback الترحيل في معاملة الافتتاح. لا تستبدل القاعدة أو
تمسحها عند خطأ الترحيل. دالة `applyOnce` تتطلب معرفًا ثابتًا وطلبًا canonical
ثابتًا عبر المحاولات. أنشئ المعرف والوقت خارج callback، واجعل كل تأثير فيه
كتابة باستخدام `Transaction` نفسه؛ قد يعيد Sembast Web تشغيل callback عند
تعارض التبويبات. لا تضع إشعارات أو اتصال شبكة داخل المعاملة.

## حدود هذه المرحلة

الويب هو المنصة المدعومة والمختبرة حاليًا. لا يوجد Backend أو حساب مستخدم أو
مزامنة خارجية. بيانات المتصفح ليست نسخة احتياطية؛ مسح بيانات الموقع يحذفها،
والتصفح الخاص أو قيود المساحة قد تمنع الاحتفاظ بها. أول تحميل يحتاج اتصالًا
أو خادمًا محليًا؛ العمل دون شبكة يحتاج اكتمال الكاش على localhost أو HTTPS.
اختبار المتصفح الحالي على Chrome؛ لم تُختبر Safari أو Firefox بعد.

الميزانيات والتقارير والنسخ الاحتياطي
تبقى للمراحل القادمة بعد موافقة صريحة. لا توجد أزرار تدّعي إنشاءها في هذه النسخة.

## المحافظ والسجل المالي

كل محفظة تنشأ بقيد افتتاحي دائم، حتى لو كان الرصيد صفرًا أو سالبًا. الرصيد
مجموع القيد الافتتاحي والتسويات والدخل والمصاريف وطرف التحويل والرسوم والقيود العكسية؛ لا يوجد حقل رصيد يمكن تعديله عشوائيًا. تصحيح
الرصيد يطلب القيمة الصحيحة والسبب، ويسجل الفرق والرصيد السابق واللاحق والتاريخ
ومعرّف العملية. العملة والقيد الافتتاحي لا يُعاد كتابتهما عند تعديل المحفظة.

تُعرض الأرصدة حسب العملة ودقتها دون جمع عملات مختلفة. يدعم الاختيار العملات
الشائعة ورمزًا مخصصًا من ثلاثة أحرف بدقة 0–6. الأرشفة تحتفظ بالسجل وتوقف التعديل
المالي حتى الاستعادة. الإخفاء يحجب المبالغ في البطاقة والتفاصيل والسجل والمجاميع
والنموذج المفتوح؛ وهو خصوصية عرض، وليس تشفيرًا لقاعدة البيانات.

اختبار Chrome للمرحلة الثانية، بعد بناء النسخة وتوليد الكاش وتشغيل الخادم:

```powershell
npm install --prefix tool
$env:KIM_URL='http://127.0.0.1:8765'
npm run test:wallets --prefix tool
```

[تقرير المرحلة الثانية](docs/phase-2-report.md) يتضمن الملفات والميزات والاختبارات
والقيود. المرحلة الثالثة موثقة أدناه.

## الدخل والمصاريف

أضف عملية من صفحة العمليات أو الرئيسية: اختر دخلًا أو مصروفًا والمحفظة
والتصنيف والمبلغ والتاريخ والملاحظات. المبلغ موجب وبعملة المحفظة ودقتها،
والرصيد يتغير فور الحفظ. سجل العمليات يدعم البحث والتصفية حسب النوع والمحفظة
والتصنيف والتاريخ والحالة، والتعديل والحذف المؤكد.

التعديل يعكس الأثر السابق ثم يسجل البديل، والحذف يلغي الأثر بقيد عكسي ويحفظ
العملية بحالة ملغاة. جميع الكتابات ذرية ومحميّة من التكرار والتعديل القديم
في تبويب آخر. العمليات القديمة تُرتب حسب تاريخها، لكن القيود تسجل بترتيب
الحفظ فلا تعيد كتابة تسوية سابقة. التاريخ المستقبلي يؤثر في الرصيد فورًا؛
لا يوجد نظام جدولة. المحافظ المؤرشفة تتطلب الاستعادة قبل تعديل عملياتها.

التصنيفات الجاهزة مترجمة؛ إدارة تصنيفات مخصصة ليست ضمن المرحلة الثالثة.
تغيير محفظة عملية أثناء تعديلها يصحح تخصيصها، وعند اختلاف العملة يطلب مبلغًا
جديدًا صريحًا؛ لا ينفذ تحويلًا أو سعر صرف. الإخفاء يحجب المبالغ في سجل العمليات
والرئيسية والنماذج المفتوحة، بما في ذلك أثناء إعادة تحميل بيانات المحافظ.

```powershell
npm run test:transactions --prefix tool
```

راجع [تقرير المرحلة الثالثة](docs/phase-3-report.md).

## التحويلات بين المحافظ

افتح «التحويلات» من صفحة المحافظ. اختر محفظتين نشطتين والمبلغ والرسوم
والملاحظات، أو بدّل المحفظتين لتحويل بالاتجاه الآخر. الرسوم بعملة المصدر.
عند اختلاف العملات أدخل سعرًا يدويًا: وحدة من عملة المصدر تساوي السعر بعملة
الاستلام. يدعم السعر حتى 12 منزلة عشرية وأرقامًا عربية؛ يحفظ مع العملية.
المبلغ المستلم يُحسب باستخدام BigInt ويُقرب لدقة عملته، والنصف إلى الأعلى.
العملة نفسها تستخدم السعر 1 حتى لو اختلفت الدقة. تُعرض المعاينة قبل الحفظ.

الخصم والإضافة والرسوم وسجل التحويل ووصل منع التكرار تُحفظ في معاملة واحدة.
أصل التحويل ليس دخلًا أو مصروفًا؛ الرسوم فقط مصروف مرتبط، ولا تُعدل أو تُحذف
من سجل العمليات مباشرة. التعديل والإلغاء يعكسان الآثار السابقة مع إبقاء
السجل ومعرّف التحويل على الطرفين. يُرفض أي خصم صافٍ لا يغطيه الرصيد الحالي،
بما فيه إلغاء تحويل صُرف مبلغ الاستلام منه. لا يعيد التعديل كتابة السجل.
التعديل الذري يفحص الأرصدة النهائية، لذا قد يوجد رصيد مؤقت سالب داخل قيود
عكس واستبدال عملية واحدة دون أن يُنشر للمستخدم كرصيد مستقل.

إخفاء إحدى المحفظتين يحجب مبالغ طرفي التحويل، لأنها قد تكشف بعضها بسعر الصرف.
الخصوصية تشمل النموذج المفتوح وتحديث البيانات بين التبويبات. الأرشفة تمنع
تغيير التحويل قبل استعادة المحفظة المعنية. إدارة العملات المتقدمة وأسعار
الصرف التلقائية ليست ضمن هذه المرحلة.

```powershell
npm run test:transfers --prefix tool
```
