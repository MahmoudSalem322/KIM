# Kim — تقرير المرحلة الثالثة: الدخل والمصاريف

تاريخ التحقق: 2026-10-11. الفرع `feature/income-expenses` يعتمد المحافظ المكتملة
عند `f626632`. main بقي عند `dbb68a4`؛ لم تُنفذ التحويلات أو المرحلة الرابعة.

## ما أُنجز

- إضافة دخل أو مصروف باختيار المحفظة والتصنيف والمبلغ والتاريخ والملاحظات،
  من صفحة العمليات أو الرئيسية. نموذج مترجم ومتجاوب مع التقويم والأخطاء
  والتحقق من المبلغ الموجب ودقة العملة، وتعطيل الإرسال أثناء الحفظ.
- سجل فعلي مرتب حسب تاريخ العملية، مع البحث في الملاحظات والتصنيف والمحفظة
  والمعرّف، والتصفية حسب النوع والمحفظة والتصنيف ونطاق التاريخ والحالة.
- تعديل نوع العملية ومحفظتها وتصنيفها ومبلغها وتاريخها وملاحظاتها. تغيير
  عملة المحفظة يفرغ المبلغ ويطلب إدخاله صراحة؛ لا توجد أسعار صرف أو تحويلات.
- حذف مؤكد يلغي أثر العملية مرة واحدة، مع إبقاء نسخة بحالة ملغاة وسجل عكسي
  قابل للتتبع. تصفية الملغاة متاحة للقراءة دون إعادة تعديلها.
- الرصيد يتحدث من القيود الفعلية؛ تفاصيل المحفظة تميز الدخل والمصروف والقيود
  العكسية، والرئيسية تعرض آخر العمليات من البيانات المحفوظة.
- العربية RTL والإنجليزية والثيمات الحالية، وحفظ دائم في IndexedDB والعمل
  دون شبكة بعد اكتمال كاش التطبيق. لا Backend أو تسجيل دخول أو بيانات وهمية.
- إخفاء مبالغ العمليات مع خصوصية المحفظة، وإفراغ مبلغ نموذج التعديل المفتوح
  عند إخفائه من تبويب آخر أو عند بدء إعادة تحميل بيانات المحافظ.

## سلامة الحسابات

المبالغ `BigInt` بوحدات صغرى نصية، دون `double` أو تقريب مالي. إنشاء العملية
يحفظ بياناتها وقيدها وأحدث مراجعة للمحفظة ووصل منع التكرار في معاملة واحدة.
الدخل يضيف مبلغًا والمصروف يخصمه. المبلغ المدخل موجب؛ أثره تحدده فئة العملية.

التعديل يضيف عكس الأثر القديم ثم الأثر البديل في المعاملة نفسها. عند تغيير
المحفظة يُصحح أثر المحفظتين ذريًا؛ أي خطأ يعيد المعاملة كلها دون نصف تغيير.
الحذف يضيف قيدًا عكسيًا ويضع علامة الإلغاء. القيد الافتتاحي والتسويات والقيود
السابقة لا تُحذف أو يُعاد كتابتها.

المعرّف والوقت ثابتان خلال إعادة المحاولة، والمُعرّف الإضافي لقيد عكس التعديل
UUID مشتق بشكل ثابت من معرّف الأمر. إعادة الأمر نفسه لا تكرر أثره، واستخدام
المعرّف نفسه لطلب مختلف يُرفض. مراجعات العملية والمحافظ تمنع الكتابة القديمة
والحذف المكرر. يُفحص أيضًا تطابق صافي القيود المرتبطة مع بيانات العملية قبل
عرضها أو عكسها؛ السجل غير المتسق لا ينتج تصحيحًا ماليًا عشوائيًا.

تاريخ العملية تاريخ تقويمي مستقل عن وقت التسجيل. العمليات القديمة تظهر حسب
تاريخها، لكن قيودها تضاف بترتيب الحفظ. مثال مُختبر: افتتاح 100، مصروف قديم 10،
ثم تسوية إلى 95؛ تعديل المصروف إلى 20 يجعل الرصيد 85 ويحافظ على التسوية،
وإلغاؤه لاحقًا يجعل الرصيد 105. لا يعيد النظام كتابة التاريخ السابق.

قاعدة البيانات إصدار 4؛ الترحيل من إصدار 3 يحافظ على المحافظ وقيودها
والإعدادات ووصول منع التكرار، دون إنشاء عمليات مالية تلقائية.

## نتائج التحقق

- `flutter analyze`: دون ملاحظات.
- `flutter test`: 51 اختبارًا ناجحًا؛ 12 اختبارًا جديدًا لمستودع العمليات و5
  لواجهتها، مع اختبارات المراحل السابقة.
- اختبارات قواعد ملفات حقيقية: الكسور والأرقام العربية والقيم الضخمة بست
  منازل، إعادة الفتح، التكرار المتزامن وتعارض المعرّفات، التعديل والإلغاء،
  نقل تخصيص عملية لمحفظة أخرى، التراجع الذري والتعارض والأرشفة، الترحيل
  الفعلي من إصدار 3، ورفض بيانات عملية لا تطابق صافي قيودها.
- اختبارات واجهة فعلية: الإضافة والتعديل والحذف والبحث، التاريخ القديم،
  النموذج العربي بعرض 390، الأموال غير الصحيحة، والخصوصية الحية وأثناء تحديث
  مؤخر للبيانات. ملاحظة المراجعة الأخيرة أُثبتت باختبار فاشل قبل إصلاحها.
- بناء Flutter Web release ناجح؛ أُعيد توليد كاش 42 ملفًا محليًا.
- فحص Chrome للمرحلة الثالثة: 11 تحققًا ناجحًا، بما فيها تعديل قديم من تبويب
  آخر، الخصوصية بين التبويبات، الإلغاء وإعادة التحميل، إنشاء مصروف حقيقي دون
  شبكة، الدخل العربي القديم، والرئيسية. لا أخطاء تشغيل أو موارد خارجية.
- فحص Chrome للمحافظ أُعيد على نسخة المرحلة الثالثة: جميع التحققات الـ15
  ناجحة، بما فيها الأرشفة والاستعادة والترتيب والتسوية والخصوصية والعمل دون شبكة.

## القيود المتبقية

- البيانات محلية للمتصفح وعنوان الموقع؛ مسحها يحذفها. النسخ الاحتياطي
  والمزامنة والتشفير خارج هذه المرحلة، والإخفاء خصوصية عرض فقط.
- التصنيفات جاهزة ومترجمة؛ إنشاء وتعديل التصنيفات المخصصة غير منفذ.
- التاريخ بين 1900 و2100. التاريخ المستقبلي يؤثر في الرصيد فور الحفظ؛ لا
  جدولة للعمليات. تاريخ التسجيل محفوظ منفصلًا عن تاريخ العملية.
- العمليات المرتبطة بمحفظة مؤرشفة للقراءة؛ استعد المحفظة قبل تعديلها أو إلغائها.
- تغيير محفظة العملية تصحيح لتخصيصها؛ لا تحويل بين محافظ أو تحويل عملات.
- Chrome هو المتصفح المختبر؛ لم تُختبر Safari وFirefox أو نسخ الهاتف الأصلية.
- العمل دون شبكة يحتاج تحميلًا أوليًا كاملًا على localhost أو HTTPS.
- main لم يُدمج، والتحويلات والمرحلة الرابعة لم تبدأ.
