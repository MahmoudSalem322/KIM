# المرحلة الثامنة — الديون والقروض

المسار `/debts` متاح من الرئيسية والمحافظ، ضمن مجموعة المحافظ في التنقل.
الواجهة مترجمة للعربية RTL والإنجليزية، وتستخدم التصميم والثيم المشتركين.
تدعم الأموال المقرضة للآخرين والمقترضة منهم، والشخص والمبلغ الأصلي والعملة
ودقتها والاستحقاق والملاحظات. تظهر الحالات النشطة والمتأخرة والمسـددة
بفلاتر منفصلة، والمبلغ المسدد والمتبقي وشريط التقدم والسجل النقدي.

## الفصل بين الإدارة والنقد

إنشاء سجل الدين أو تعديل بياناته إجراء إداري فقط: لا يتغير رصيد ولا
يُنشأ دخل أو مصروف. تسجيل الأصل النقدي إجراء منفصل وصريح، مرة واحدة
لكل سجل نشط، بمبلغ يطابق أصل الدين. يمكن استيراد اتفاق قديم إداريًا ثم
تسجيل دفعاته الحالية دون إعادة تسجيل أصل سبق دخوله في الرصيد الافتتاحي.

| الحركة | أقرضت الآخرين | اقترضت منهم |
|---|---|---|
| إنشاء سجل إداري | بلا أثر نقدي | بلا أثر نقدي |
| تسجيل الأصل النقدي | خصم من المحفظة | إضافة للمحفظة |
| دفعة سداد | إضافة للمحفظة | خصم من المحفظة |
| إلغاء حركة | عكس أثرها السابق | عكس أثرها السابق |

كل دفعة تختار محفظة نشطة بنفس العملة والدقة، وتاريخًا وملاحظة اختيارية.
السداد الجزئي والكامل يخفض المتبقي؛ تجاوز المتبقي مرفوض. السداد الكامل
يجعل الحالة مسـددة، وإلغاء دفعة يعيد حسابها فورًا. التأخر يبدأ في اليوم
التالي للاستحقاق؛ المستحق اليوم يبقى نشطًا. الحالة المالية محسوبة من
الحركات الفعلية غير الملغاة، وليست علمًا مخزنًا قد يصبح قديمًا.

تعديل مبلغ أو محفظة دفعة يعكس القيد السابق ويسجل البديل ذريًا. الإلغاء
يحفظ السجل والقيد العكسي بدل الحذف. يمكن أيضًا تصحيح محفظة أو تاريخ
الحركة النقدية الأصلية أو إلغاؤها. أصل الدين الإداري ونوعه وعملته تثبت
بعد أول حركة، حتى إذا ألغيت لاحقًا، للحفاظ على معنى السجل القديم؛ يظل
الشخص والاستحقاق والملاحظات قابلة للتعديل.

## السلامة المالية والتخزين

- `Money` و`BigInt` لجميع المبالغ والمقارنات والحسابات؛ `double` فقط
  لهندسة شريط تقدم محدود. لا تُجمع مبالغ بعملات مختلفة.
- إصدار قاعدة البيانات **8**، بمخزني `debts` و`debt_cash_events` دون
  ديون افتراضية أو تغيير بيانات المراحل السابقة.
- معرّفات ثابتة وطلبات معيارية وإيصالات `applyOnce` تمنع تكرار الحركات
  عند الإعادة، مع مراجعة الدين والمحافظ لكشف التعارض بين التبويبات.
- القيود `debtIn/debtOut/debtReversal` تربط الحركة عبر `debtEventId`.
  تحديث المحفظة والحركة والدين والإيصال في نفس معاملة Sembast.
- تحقق من **الأثر النهائي** بعد جميع أرجل التعديل؛ لا تُرفض عملية صحيحة
  بسبب عكس وسيط. يُمنع الخصم فوق الرصيد المتاح، وعكس استلام صُرفت أمواله.
- حماية حجوزات الادخار تطبق على الدفع وعكس الاستلام وتعديل المحافظ؛
  فشل الحماية يتراجع عن كل القيم والقيود والإيصال.
- أصل القرض وسداده ليسا دخلًا أو مصروفًا. تظهر الأرصدة النقدية الصحيحة
  في المحافظ والرئيسية، ولا تدخل هذه المبالغ في مخططات الدخل والمصاريف
  أو الميزانيات. سجل التفاصيل في الديون ودفتر المحفظة.
- المحفظة المؤرشفة ترفض تغيير حركاتها حتى استعادتها. الإخفاء يحجب
  المبالغ والحالة والتقدم وسجل المبالغ، ويوقف النموذج المفتوح إذا تغيرت
  البيانات أو الخصوصية، دون عرض قيم محتفظ بها أثناء إعادة التحميل.

## الملفات والتحقق

تعريف المجال والعقد والتخزين والواجهة في `lib/features/debts/`، مع
ربط التهيئة والمسار وعنوان التطبيق في `lib/app/`. تغير دفتر المحفظة
لعرض أنواع حركات الديون وروابطها، والرئيسية والمحافظ للوصول للقسم.
الترقية في `lib/core/data/app_database.dart`، وتوقع ترقية اختبار
الادخار السابق أصبح يتبع رقم الإصدار الحالي.

نجح التحليل دون ملاحظات، ونجحت **155 اختبارًا** (18 لاختبارات تخزين
وحسابات الديون و4 للواجهة، إضافة إلى جميع اختبارات المراحل السابقة).
بناء Flutter Web محلي الموارد نجح، وكاش العمل دون إنترنت يتضمن 42 ملفًا.
بعد عزل زر فتح سجل الحركات في شجرة الوصول، أُعيد التحليل واختبارات
واجهة الديون الأربعة ونجحت. نجحت **11 مجموعة تحقق Chrome** على البناء
النهائي: ترقية بيانات السابعة، والفصل الإداري والنقدي، والاتجاهان، وتعديل
الدفعات وإلغاؤها وتغيير المحفظة، والسداد الزائد والعملات، والعمل دون
إنترنت والخصوصية والعربية الداكنة عند 390 بكسل؛ بلا أخطاء تشغيل أو
طلبات موارد خارجية. صور التحقق محفوظة مع التقرير.

اختبارات الديون تغطي الاتجاهين، والفصل الإداري والنقدي، والتعديل والإلغاء
والسداد الزائد، وتغيير المحفظة، وإعادة التنفيذ وإعادة الفتح، والتزامن
والتراجع، والحجوزات ونقص الرصيد والخصوصية والأرشفة والعملات والدقة
والمبالغ الكبيرة، والحالات والتواريخ وترقية الإصدار السابق.

فحص Chrome الفعلي في `tool/debts_browser_smoke.cjs`، ونتائجه في
`phase-8-browser-validation.json`. يستخدم ملف اختبار معزولًا، ويمكن تمرير
ملف اختبار السابعة عبر `KIM_LEGACY_PROFILE` لفحص ترقية IndexedDB والكاش.
يجب أن يبقى العنوان والمنفذ نفسهما، ويُغلق عملاء الإصدار السابق لتفعيل
service worker الجديد. لا تستخدم ملف المتصفح الشخصي.

## الحدود

لا فوائد أو غرامات أو جدولة دفع تلقائية أو تذكيرات، ولا شطب إداري
للدين أو تحويل مباشر بين عملتي الدين والمحفظة. التحويل للعملة المطلوبة
يتم بأداة التحويلات قبل تسجيل الحركة. تسجيل حركة بتاريخ معين ينفذ
أثرها النقدي الآن؛ ليس أمرًا مجدولًا. قد يصبح الدين متأخرًا عند فتح أو
إعادة عرض الصفحة في يوم جديد. لا حذف نهائي للتاريخ المالي.

أنشئ `feature/debts-loans` من `main` الحالي عند `c5b65aa` ثم أضيف اعتماد
السابعة `4eff2e9` داخل الفرع. لم يتغير `main`، ولم يتم الدفع إلى GitHub.
