# دليل إصدار Kim 1.0.0 على الويب

Kim تطبيق ثابت بالكامل: لا خادم تطبيق ولا قاعدة بيانات بعيدة ولا تسجيل دخول.
النشر هو رفع مجلد `build/web` إلى أي استضافة ملفات ثابتة تدعم HTTPS.

## 1. بوابات الجودة قبل البناء

```sh
flutter pub get
flutter analyze
dart format --output=none --set-exit-if-changed lib test tool
flutter test --concurrency=1
```

مجموعة `test/release/` هي بوابة الإصدار: دورة مالية كاملة على قاعدة ملفات
حقيقية مع إعادة الفتح والنسخ والاستعادة، ومصفوفة الشاشات من 320 إلى 1440
بكسل، وحجم البيانات، واتساق رقم الإصدار، وقواعد كاش العمل دون إنترنت.

## 2. البناء الإنتاجي

```powershell
powershell -ExecutionPolicy Bypass -File .\tool\build_web.ps1
```

`-ExecutionPolicy Bypass` يخص هذا الأمر فقط ولا يغير إعدادات النظام. أو:

```sh
flutter build web --release --no-web-resources-cdn --pwa-strategy=none --base-href /
dart run tool/generate_offline.dart
```

في Git Bash على Windows اكتب `MSYS_NO_PATHCONV=1` قبل `flutter` حتى لا يتحول
`/` إلى مسار Windows. للنشر داخل مجلد فرعي استخدم `--base-href /kim/`
(أو `-BaseHref /kim/`)، ويجب أن يبدأ وينتهي بشرطة مائلة.

`generate_offline.dart` يقرأ إعداد المحمّل المولّد ويحذف من مجلد البناء ما
لا يمكن طلبه: ملفات `.symbols` للتصحيح، ومحركات skwasm/wimp/webparagraph
عندما لا يستخدمها البناء. ثم يكتب `offline_worker.js` بقائمة الملفات
المتبقية ومراجعة جديدة. أي إعداد محمّل غير معروف يُبقي كل الملفات. يجب
تشغيله بعد كل بناء؛ بناء بدونه لا يسجل عامل الخدمة.

الحجم المتوقع لهذا الإصدار: 28 ملفًا، نحو 21.7 MiB (كان 45.5 MiB)، منها
`main.dart.js` بنحو 5.1 MiB وCanvasKit المحلي والخطوط العربية واللاتينية.

## 3. متطلبات الاستضافة

- **HTTPS** إلزامي (أو localhost للتجربة). عامل الخدمة وIndexedDB لا يعملان
  عبر `file://`.
- أنواع MIME: `.js` ← `text/javascript`، `.wasm` ← `application/wasm`،
  `.json` ← `application/json`، `.ttf` ← `font/ttf`. المحمّل يرفض تسجيل
  عامل الخدمة إذا لم يكن نوع `offline_worker.js` جافاسكربت.
- ترويسات الكاش المقترحة: `Cache-Control: no-cache` للملفات
  `index.html` و`flutter_bootstrap.js` و`offline_worker.js` و`version.json`،
  حتى يكتشف المتصفح الإصدار الجديد. أسماء الملفات الأخرى غير مُجزّأة بالبصمة،
  لذلك لا تضع لها `immutable` أو مدة طويلة؛ `no-cache` أو مدة قصيرة كافية لأن
  عامل الخدمة يخدمها من كاشه بعد التثبيت.
- لا حاجة لإعادة كتابة المسارات: التطبيق يستخدم مسارات `#/` ولا يطلب أي
  مورد من نطاق خارجي.
- المصدر (scheme + host + port + base-href) هو هوية بيانات المستخدم في
  IndexedDB. تغيير النطاق أو المنفذ يبدأ مساحة فارغة؛ انقل البيانات عبر ملف
  نسخة احتياطية `.kim` من الإعدادات.

## 4. التحقق من البناء المنشور

```powershell
npm install --prefix tool
$env:KIM_URL='https://your-host/'   # أو http://127.0.0.1:8765 محليًا
npm run test:release --prefix tool
```

يقيس فحص الإصدار زمن أول إطار للتحميل الأول والتحميل من الكاش، ويتحقق من
حجم الكاش، وإعادة التحميل دون شبكة لكل الصفحات بعرض 320/768/1440 بكسل،
وحفظ دورة مالية عبر الواجهة، وغياب أخطاء الصفحة والطلبات الخارجية. فحوص
المراحل `test:wallets` … `test:security` تبقى متاحة للانحدار التفصيلي.

## 5. التحديث والرجوع

- عند نشر إصدار جديد يثبّت عامل الخدمة كاشًا كاملًا جديدًا في الخلفية، ولا
  يُفعّل إلا بعد اكتمال التنزيل وإغلاق تبويبات الإصدار القديم. لا تُخلط ملفات
  إصدارين.
- قاعدة البيانات بالإصدار 11، مثل المرحلة الحادية عشرة؛ الرجوع إلى بناء
  المرحلة 11 آمن. بناء أقدم من 11 يرفض قاعدة أحدث صراحة ولا يمسحها.
- احتفظ بنسخة من مجلد البناء السابق للرجوع السريع. البيانات المحلية لا
  تتأثر بإعادة النشر.

## 6. حدود معروفة

- الاختبار الآلي للمتصفح على Chrome فقط؛ Firefox وSafari لم يُختبرا آليًا.
- التحميل الأول يحتاج اتصالًا لتنزيل نحو 13 MiB قبل أول إطار، ثم يكمل عامل
  الخدمة الكاش في الخلفية.
- مسح بيانات الموقع يحذف البيانات؛ النسخ الاحتياطي `.kim` مسؤولية المستخدم.
- قفل PIN قفل واجهة وليس تشفيرًا لقاعدة المتصفح.
