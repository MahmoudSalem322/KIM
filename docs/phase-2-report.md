# Kim — تقرير المرحلة الثانية: المحافظ المالية

تاريخ التحقق: 2026-10-11. الأساس هو main عند `dbb68a4`، والتنفيذ على
`feature/wallet-management`. لا تشمل هذه المرحلة الدخل والمصاريف العامة أو
التحويلات، ولم يبدأ تنفيذ المرحلة الثالثة.

## الميزات المنجزة

- إنشاء محافظ دون حد عددي يفرضه التطبيق، مع الاسم واللون والأيقونة والنوع
  والعملة والرصيد الافتتاحي. العملات الشائعة متاحة، مع رمز مخصص من ثلاثة أحرف
  ودقة 0–6. الرصيد الافتتاحي يقبل الصفر والقيم السالبة والأرقام العربية.
- بطاقات متجاوبة وصفحة تفاصيل مستقلة لكل محفظة؛ تعديل بياناتها الوصفية،
  ترتيبها للأعلى والأسفل، أرشفتها واستعادتها، وإخفاء رصيدها.
- سجل افتتاحي دائم، وتسوية موثقة تعرض الفرق والرصيد السابق واللاحق والسبب
  والتاريخ ومعرّف العملية. تعديل البيانات الوصفية يحافظ على العملة والقيد
  الافتتاحي. الأرشفة تمنع التعديل والتسوية حتى الاستعادة وتحافظ على السجل.
- حفظ فعلي في IndexedDB عبر Sembast Web، ودعم العمل دون شبكة بعد اكتمال
  تثبيت كاش نسخة الويب. لا توجد بيانات مالية وهمية أو خدمات خلفية.
- عرض إجماليات المحافظ النشطة حسب العملة ودقتها؛ إخفاء أحد الأرصدة يحجب
  إجمالي مجموعته. الإخفاء يشمل التفاصيل والسجل والنموذج المفتوح في تبويب آخر.
- العربية RTL والإنجليزية والثيمات الحالية ونظام التصميم المحلي؛ حالات
  التحميل والخطأ وإعادة المحاولة والفراغ. الرئيسية تعرض بيانات المحافظ الفعلية.

## سلامة المال والتخزين

المبالغ وحدات صغرى من `BigInt` تُخزّن كنص، دون استخدام `double` للحسابات.
الرصيد مشتق من قيود ثابتة؛ تُفحص سلسلة القيود وعملاتها وأرصدة ما قبل/بعد كل
عملية، ويُرفض السجل المفقود أو غير المتسق بدل اختلاق رصيد بديل.

إنشاء المحفظة وقيدها الافتتاحي ووصل منع التكرار تُحفظ في معاملة واحدة.
التسويات تحفظ القيد وتحديث المراجعة ووصل العملية ذريًا. إعادة الطلب نفسه بنفس
المعرّف لا تكرر تأثيره؛ اختلاف الطلب مع المعرّف نفسه يُرفض. النماذج تحتفظ
بمعرّف العملية عند إعادة المحاولة وتعطّل الإرسال أثناء الحفظ.

تُراجع نسخة المحفظة قبل التعديل والتسوية والأرشفة والإخفاء، وجميع نسخ المحافظ
قبل إعادة ترتيبها. الطلب القديم من تبويب آخر يُرفض ولا يكتب فوق الحالة الأحدث.
قاعدة البيانات أصبحت بالإصدار 3، مع ترحيل يحافظ على الإعدادات ووصول العمليات
السابقة، دون حذف البيانات أو إعادة إنشاء القاعدة.

## الاختبارات والتحقق

- `flutter analyze`: دون أخطاء أو تحذيرات تحليل.
- `flutter test`: جميع الاختبارات الـ34 ناجحة، منها 11 للمستودع و4 لواجهة المحافظ.
- بناء Flutter Web بنمط release ناجح، وجميع الموارد محلية؛ أُعيد توليد كاش
  العمل دون شبكة ويضم 42 ملفًا.
- اختبارات المستودع تستخدم قاعدة ملفات حقيقية وتعيد فتحها؛ تشمل الترحيل من
  الإصدار 2، القيم الضخمة والصفر والسالب، التكرار وتعارض المعرّفات، التسوية
  الدقيقة، التراجع الذري، الأرشفة والإخفاء والترتيب ورفض السجل غير المتسق.
- اختبارات الواجهة تشمل إنشاء المحفظة وتفاصيل القيد، حفظ الافتتاح عند التعديل،
  إخفاء المبالغ، النموذج العربي على عرض 390، وتغيير الخصوصية أثناء فتح التسوية.
- مراجعة مستقلة للميزة كاملة ومراجعة لاحقة لإصلاح الخصوصية؛ أُغلق العيب المكتشف
  باختبار تراجع يثبت مسح المبلغ السابق وإخفاء النموذج المفتوح.
- فحص Chrome النهائي: 15 تحققًا ناجحًا، دون أخطاء تشغيل أو طلبات خارجية.
  أثبت رفض التسوية والترتيب القديمين بين تبويبين، وحفظ تعديل فعلي أثناء انقطاع
  الشبكة بعد إعادة التحميل. فُحصت قيمة `900719925474099312345.17` على JavaScript
  وعملة مخصصة بدقة ست منازل وقيمة افتتاحية عربية سالبة.

## القيود المتبقية

- البيانات محلية لعنوان الموقع والمتصفح والمنفذ. مسح بيانات الموقع يحذفها؛
  النسخ الاحتياطي والمزامنة خارج نطاق هذه المرحلة، وقيود مساحة المتصفح قائمة.
- الإخفاء خصوصية عرض وليس تشفيرًا. يُسمح بتغييره للمحفظة المؤرشفة أيضًا.
- العملة ودقتها ثابتتان بعد الإنشاء للحفاظ على صحة القيود؛ عند اختيار عملة
  خاطئة تُنشأ محفظة جديدة وتؤرشف القديمة.
- التشغيل دون شبكة يحتاج تحميلًا أوليًا كاملًا على localhost أو HTTPS.
- فحص المتصفح على Chrome؛ Safari وFirefox وتطبيقات الهاتف الأصلية لم تُختبر.
- لا دخل أو مصاريف عامة أو تحويلات أو ميزانيات أو تقارير مالية بعد؛ هذه مراحل
  مستقلة تحتاج موافقة صريحة. فرع المرحلة الثانية لا يُدمج في main تلقائيًا.
